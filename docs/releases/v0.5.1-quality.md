# Luma 0.5.1 — release qualification record

On 2026-10-20 the project owner explicitly selected: «Выпустить 0.5.1 после CI
с указанными ограничениями». This authorizes publication of 0.5.1 after CI with
the following 23 functional coverage gaps. It is a release exception, not a full
UX PASS or a waiver for subsequent releases. Remaining qualification continues in
[Issue #48](https://github.com/yakut-sekonts/Luma/issues/48), following Issue #46.

## Required before publication

The existing release workflow must pass build, bounded functional tests, static
analysis, standalone launch without developer SDKs, mounted-DMG verification,
version/provenance/checksums, Sparkle archive signing against the embedded public
key, and verification of uploaded release assets. Failures in those checks still
block publication. This exception does not weaken or remove a test assertion.

## Completed evidence

The regression work fixes 34 reproduced production defects. The latest local
product-code cohort has 30 focused UX PASS across Cocoa/Metal and software,
53 functional CTest PASS, one optional Nikon fixture SKIP, and 141 infrastructure
PASS. Tests and source/binary attestations for the two separate UX cohorts are
recorded in [UX_QUALIFICATION_STATUS.md](../testing/UX_QUALIFICATION_STATUS.md).
These counts are not all distinct scenarios and do not claim coverage of the
contracts below. Hosted CI and release packaging run separately on their actual
source revisions. The full qualification runner remains NOT_QUALIFIED.

## Deferred workload and platform limits

Load, stress, soak, chaos and performance remain deferred until pre-1.0.0 by
explicit user direction. The policy records 112 deferred implemented workloads
and 51 deferred unadapted checks; none counts as PASS. Conditional mask
duplication is unavailable and the original-SHA invariant is a suite-wide
integrity check, so neither adds a missing functional adapter to the 23 above.

The app is ad-hoc signed, not Developer ID signed or notarized. Gatekeeper may
require Privacy & Security → Open Anyway on first launch. Sparkle uses Ed25519
archive signatures; this is distinct from Apple notarization.

Catalog schema 11 is not readable by older Luma versions. Preserve a catalog
backup before upgrading if rollback is needed; automatic backup is not part of
this release. Original photo files remain unchanged.
